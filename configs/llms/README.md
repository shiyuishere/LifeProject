# Specification of LLM Configuration

This directory contains configuration files for LLM API providers.
Each provider (e.g., OpenAI, Anthropic) can have multiple models, each defined by a separate YAML configuration file.

## Configuration file

- `XXX.yaml`: Defines a single model’s parameters and operational limits.
- `README.md`: This documentation file.

## Configuration format

The configuration file adopts the YAML format and supports the reference of environment variables. The basic structure is as follows:

```yaml
provider: "openai"
base_url: "https://api.openai.com/v1"
api_key: "${OPENAI_API_KEY}"

model: "gpt-4o-mini"
mark: "G4O-mini"

temperature: 0.0
max_tokens: 16000
concurrency: 5

input_price: 0.15
output_price: 0.60
rate_limit_tpm: 30000
context_window: 128000
```

## Explanation of configuration parameters

### Basic Information Configuration

- `provider`: Name of the LLM provider.
- `base_url`: The basic access address of the API, used to construct the request path.
- `api_key`: API key, which can be referenced through environment variables (e.g., `${API_KEY_NAME}`).

### Model Parameter Configuration

- `model`: Name of the specific model to be used.
- `mark`: Model identifier, used for log recording, file naming, and result tracking.

### Operational Parameter Configuration

- `temperatures`: Temperature parameter, controlling the randomness of the model output.
- `concurrency`: Upper limit of concurrent requests, used to limit the number of concurrent requests for each model. Setting it too low will reduce efficiency, while setting it too high may trigger rate limits.
- `max_tokens`: Maximum output length generated by the model each time (unit: token).

### Billing and Limit Parameter Configuration

- `input_price`: Unit price of input tokens (unit: US dollars / million tokens).
- `output_price`: Unit price of output tokens (unit: US dollars / million tokens).

## Environment Variable Setup

Create a `.env` file in the root directory of the project and set the corresponding API keys:

```env
# OpenAI API
OPENAI_API_KEY=your_openai_api_key_here

```

## Explanation of Temperature Parameters

The temperature parameter controls the randomness of the model's output:
- `0.0`: The most deterministic, resulting in the most consistent output.
- `0.3`: Low randomness, suitable for tasks that require stability.
- `0.5`: Medium randomness, balancing creativity and consistency.
- `0.7`: High randomness, suitable for tasks that demand creativity.
- `1.0`: The highest randomness, leading to the most diverse output.

## Precautions

1. **API Key Security**: Do not write the API key directly into the configuration file. Always use environment variables.
2. **Cost Control**: The call costs of different models vary significantly. Please select an appropriate model according to your needs.
3. **Availability**: Ensure that the configured models are available in the corresponding providers.
4. **Rate Limiting**: Pay attention to the API call frequency limits of each provider.


## Troubleshooting

### Common Issues

1. **Configuration file not found**: Ensure that the `XXX.yaml` file exists in the correct path.
2. **Environment variables not set**: Check if the API keys in the `.env` file are set correctly.
3. **Model unavailable**: Verify that the model name is available in the corresponding provider.
4. **API call failure**: Check the network connection and the validity of the API key.

### Debugging Suggestions

- Enable detailed log output.
- Check the API response status code.
- Verify that the environment variables are loaded correctly.
